# Internal-Whitehack-Pipeline

自組織のセキュリティ・業務統制・個人情報管理の弱点を安全に確認し、是正・再検証・経営報告につなぐ「台帳駆動の統制改善パイプライン」の設計・構築計画です。現在のリポジトリには設計文書があり、実行可能な自動化コードや本番導入済みサービスは含まれていません。

## 用語と利用例

ここでの「ホワイトハック」は、許可された範囲で自組織の統制を改善する取り組みを指します。「台帳」は資産・権限・リスク・是正作業を追跡する記録、「再検証」は対応後に完了条件を満たすか確かめる工程です。

架空の例では、Driveの外部共有候補を台帳に記録し、担当者が業務上必要かを確認します。是正が必要なら責任者・期限・完了条件を設定し、承認を得た担当者が対応した後に再検証します。候補の抽出と本番設定の変更を分ける流れです。

## 設計の考え方

[最適化設計・構築計画](docs/20260513-optimized-internal-whitehack-pipeline-plan.md)は、初期90日では攻撃的な演習より、棚卸し・安全な検証・是正・報告を優先します。人間が誤検知、リスク評価、リスク受容を判断し、AIによる本番設定の自動変更、無許可の侵入テスト、要配慮個人情報を使った検証は初期対象外です。

## 技術的背景

計画上の最小構成は、Google Sheetsの台帳、アクセスを制限したDriveの証跡、Chat/Gmailの通知、Calendarの予定、Apps Scriptの自動化です。入力を台帳化し、検出・分類、人間のレビュー・承認、是正・再検証、週次・月次報告へ進めます。管理APIへの接続や権限の設定、コードの実装は別途必要です。

## 成立の経緯

原文書は2026-05-13作成で、既存の複数の設計・構築計画を統合レビューしたものです。重いRed/Blue/Purple Team体制から始める案と比較し、初期90日に回せる台帳中心の構成を推奨しています。この日付は文書の作成日であり、導入や運用開始を示しません。

## 展開

初期対象はGoogle Workspace、入退社・異動、SaaS、個人情報の保存場所、端末・復旧、委託先管理です。四半期以降の机上演習、外部専門家レビュー、限定的な技術診断や、DB・BigQuery等への移行は次段階の候補です。導入時は計画書のスコープ・承認・停止条件を組織で確認し、実行可能な範囲を確定してから進めます。
